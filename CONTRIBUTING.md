# Разработка

Как устроен проект и что нужно знать перед правками. Всё ниже взято из кода и из прогонов при создании проекта (05.10.2026); то, что не выяснено, помечено «уточнить».

Нашли ошибку или принтер, на котором скрипт ведёт себя не так, — откройте issue и приложите вывод `Fix-PrinterWiFi.cmd -WhatIf`. Перед отправкой замените в нём свои IP, MAC, имена хостов и компьютеров на выдуманные.

## Что это

Универсальный фиксер медленной печати на сетевом принтере в Windows. Переводит очередь печати с поиска принтера по имени (LLMNR/mDNS) или с WSD на прямой TCP/IP-порт и удаляет сетевые дубли этого принтера.

Вырос из скрипта для одного офисного МФУ Pantum — там то же самое, но с зашитыми адресом, MAC и моделью принтера. Здесь зашитых адресов и моделей нет: принтер выбирает мастер и описывает файл настроек.

**Для кого.** Тот, кто настраивает ПК в небольшом офисе без домена: мастер запускается один раз, дальше папку копируют на каждый компьютер и запускают двойным щелчком.

## Стек

- **Windows PowerShell 5.1** — скрипты и лаунчер вызывают `powershell.exe`. `#Requires` нет. Под PowerShell 7 не проверялось.
- **Batch** — лаунчер `.cmd`.
- Сторонних зависимостей, сборки и CI нет.
- Встроенные модули Windows: `PrintManagement`, `NetTCPIP`, `PnpDevice`, `CimCmdlets`, `DnsClient`, `ScheduledTasks`; утилита `PrintBrm.exe`; классы .NET `TcpClient`, `Ping`, `Dns`.
- Проверялось на Windows 11 Pro. Минимальная версия Windows — уточнить.

## Архитектура

Два самодостаточных скрипта, общего модуля нет. Связывает их файл настроек и имя очереди.

```
Fix-PrinterWiFi.cmd ──► Fix-PrinterWiFi.ps1 ──► printer.psd1 (пишет мастер, читают оба скрипта)
                                │
                                └─ создаёт очередь QueueName на порту IP_<адрес>
Printer-Watchdog.ps1 ── ищет очередь по QueueName, принтер — по PrinterMac
```

### Настройки

Порядок приоритета: параметр командной строки → `printer.psd1` → значение по умолчанию (`PortNumber` = 9100). Файл читается функцией `Read-ConfigFile`: текст как UTF-8 (с BOM или без), разбор парсером PowerShell и `SafeGetValue()` — код из файла не выполняется.

Ключи: `PrinterIP`, `PrinterMac`, `PrinterHostName`, `DriverName`, `QueueName`, `MatchPattern`, `PortNumber`. Обязательны `PrinterIP`, `DriverName`, `QueueName`; для сторожа — `QueueName` и `PrinterMac`.

### Fix-PrinterWiFi.ps1

1. **Настройки.** Если задан `-Setup` или `PrinterIP` неизвестен, запускается мастер `Invoke-Setup`: находит сетевые очереди ПК, группирует по IP, определяет MAC (ARP), имя хоста (порты на имя, обратный DNS), драйвер производителя и имя очереди, пишет `printer.psd1`. С `-Setup` на этом работа заканчивается; при автозапуске мастер спрашивает, исправлять ли сразу.
2. **Права.** Без `-WhatIf` и без прав администратора — перезапуск через UAC с передачей **всех** заданных параметров и пути к файлу настроек; код возврата 99.
3. **Шаг 1.** Связь с принтером (`Measure-PrinterResponse`: TCP 80, 443, 631, затем ping) и сверка MAC, если он задан.
4. **Шаг 2.** `Get-NetworkQueues` собирает сетевые локальные очереди, каждой присваивается отношение `Ours` / `Other` / `Unknown` и причина. Выбирается, что оставить (`$keep`), удалить (`$toRemove`), не трогать (`$fax`, `$protected`, `$unknown`), и какие порты станут лишними (`$stalePorts`). План печатается, затем запрос подтверждения.
5. **Шаги 3–7.** Бэкап PrintBrm → порт → очередь (порт, драйвер, имя) → удаление дублей и портов, принтер по умолчанию → итог.

Правила `Ours`, по порядку: имя равно `QueueName` → порт ведёт на `PrinterIP` → порт указывает на имя хоста принтера → (если адрес известен и другой — `Other`, стоп) → имя хоста в названии очереди → `MatchPattern`. Иначе `Unknown`.

Адрес WSD-очереди: очередь → её устройство PnP (`PrintQueue`) → `ContainerId` → сетевые устройства того же контейнера (`SWD\DAFWSDPROVIDER`, `SWD\ESCL`, `SWD\IPP`) → свойства PnP-X с адресом (`Get-PnpDeviceIPs`).

Все `throw "… Ничего не изменено."` стоят до шага 3. Новые проверки должны сохранять этот порядок.

### Printer-Watchdog.ps1

- `-Install` — копирует себя в `%ProgramData%\PrinterWiFiFix\`, регистрирует задачу `Printer Wi-Fi Watchdog - <имя очереди>` (от `SYSTEM`, при старте и каждые `-IntervalMinutes` минут) и записывает настройки в аргументы задачи. Установленной копии файл настроек не нужен.
- `-Uninstall` — удаляет задачу этой очереди; копию скрипта — только если не осталось задач других очередей.
- без ключей — разовая проверка: если по адресу порта очереди отвечает устройство с нужным MAC, выход. Иначе поиск по MAC (ARP, mDNS, пинг подсети /24) и перевод очереди на новый порт.

## Команды

Установки и сборки нет. Запускать из папки проекта.

```powershell
# Мастер: выбрать принтер и записать printer.psd1 (ничего не исправляет)
.\Fix-PrinterWiFi.cmd -Setup

# Пробный прогон: показать план, ничего не меняя (права администратора не нужны)
.\Fix-PrinterWiFi.cmd -WhatIf

# Боевой запуск (то же, что двойной щелчок; запросит UAC и подтверждение плана)
.\Fix-PrinterWiFi.cmd

# Сторож
powershell -ExecutionPolicy Bypass -File .\Printer-Watchdog.ps1 -Install
powershell -ExecutionPolicy Bypass -File .\Printer-Watchdog.ps1 -Uninstall
powershell -ExecutionPolicy Bypass -File .\Printer-Watchdog.ps1            # разовая проверка

# Откат (точная команда печатается скриптом и сохраняется в логе)
& "$env:WINDIR\System32\spool\tools\PrintBrm.exe" -R -F "<файл .printerExport>"
```

Автотестов в репозитории нет. Доступные проверки:

```powershell
# Синтаксис и BOM: для каждого файла должно быть 0 ошибок и EFBBBF
foreach ($f in 'Fix-PrinterWiFi.ps1','Printer-Watchdog.ps1') {
    $t = $null; $e = $null
    [void][System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path $f), [ref]$t, [ref]$e)
    $bom = ([IO.File]::ReadAllBytes((Resolve-Path $f))[0..2] | ForEach-Object { $_.ToString('X2') }) -join ''
    "${f}: ошибок $($e.Count), начало $bom"
}
```

Логику разбора очередей при создании проекта проверяли так: в отдельном процессе PowerShell командлеты `Get-Printer`, `Get-PrinterPort`, `Get-PrinterDriver`, `Get-PnpDevice`, `Get-PnpDeviceProperty`, `Get-CimInstance` подменялись **алиасами** на функции с подставными данными, затем скрипт запускался с `-WhatIf`. Подмена глобальными функциями не работает: `Import-Module` внутри скрипта возвращает настоящие. Мастер с вводом проверяется подачей ответов на stdin: `'1','' | powershell -File .\Fix-PrinterWiFi.ps1 -Setup -Config <временный файл>`.

## Конфигурация и хранилище

Переменных окружения проект не требует; используются стандартные `ProgramData`, `COMPUTERNAME`, `WINDIR`. Секретов нет. Единственный чувствительный файл — `printer.psd1` (данные локальной сети).

Базы данных нет. На каждом ПК в `%ProgramData%\PrinterWiFiFix\`:

- `Fix-PrinterWiFi_<ПК>_<дата_время>.log` — транскрипт боевого запуска;
- `printers-before_<ПК>_<дата_время>.printerExport` — бэкап PrintBrm;
- `watchdog.log` (общий для всех очередей, в строке указано имя очереди; ротация на 512 КБ в `.old`);
- `Printer-Watchdog.ps1` — установленная копия сторожа.

## Развёртывание

Вручную: на первом ПК мастер создаёт `printer.psd1`, затем папку вместе с этим файлом копируют на остальные ПК и запускают `Fix-PrinterWiFi.cmd`. Исходники — в репозитории `github.com/exuupery/printer-wifi-fix`.

## Соглашения

- Комментарии, справка и сообщения пользователю — на русском; идентификаторы — на английском; комментарии в `.cmd` — на английском, чистый ASCII.
- Функции `Verb-Noun`, параметры `PascalCase`, локальные переменные `camelCase`.
- `.ps1` и `.psd1` — UTF-8 **с BOM**, CRLF. `.cmd` — ASCII, CRLF.
- Вывод в фиксере — через `Write-Step` / `Write-Ok` / `Write-Info` / `Write-Warn`; в стороже — через `Write-Log`.
- Разделы кода отделяются комментариями `# --- Название ---…`, шаги пронумерованы и совпадают с заголовками `Write-Step`.
- `$ErrorActionPreference = 'Stop'`; каждое изменяющее действие в фиксере обёрнуто в `$PSCmdlet.ShouldProcess(...)`.
- В строках сообщений в роли тире — обычный дефис `-`.
- Сообщения об ошибках говорят, что делать дальше, и заканчиваются «Ничего не изменено.», когда это правда.
- Коды возврата обоих скриптов: 0 — готово, 1 — ошибка, 99 — перезапущен с правами администратора в новом окне.

## Что проверено, а что нет

Проверено 05.10.2026 на одном ПК (Windows 11, сетевой МФУ Pantum), без боевых запусков:

- мастер (`-Setup -Yes` и с вводом на stdin), пробный прогон `-WhatIf` на реальных очередях;
- разбор очередей на подставных данных: дубли на имени хоста, WSD-очередь со сканером, факс, второй принтер той же модели на другом IP, общий принтер, виртуальный принтер; ключи `-RemoveFax` и `-RemoveNetworkScanner`;
- ошибки: неверный MAC, нет драйвера, имя очереди занято USB-очередью, неинтерактивный запуск без `-Yes`;
- разовая проверка сторожа, лаунчер с `-WhatIf`, экранирование аргументов при повышении прав.

**Не проверено:** боевой запуск этой версией (шаги 3–6 с реальными изменениями), определение адреса на настоящих WSD-устройствах (имена свойств PnP-X взяты по памяти и проверены только на модели), принтеры других производителей, `-Install`/`-Uninstall` сторожа и его реакция на смену IP, цепочка «автозапуск мастера → UAC → исправление».

## Неочевидные места

- **BOM обязателен.** Windows PowerShell 5.1 читает `.ps1` без BOM в ANSI-кодировке, и кириллица ломается. Инструменты редактирования могут сохранить файл без BOM и с LF — после правок проверять командой выше. `printer.psd1` это не касается: он читается явно как UTF-8.
- **`Set-Variable` и `-WhatIf`.** Под `-WhatIf` он ничего не присваивает, поэтому при чтении настроек стоит `-WhatIf:$false`. То же относится к любым служебным командлетам с `ShouldProcess`.
- **`Read-Host` в неинтерактивном сеансе** возвращает `$null`, а не бросает исключение; `Read-Answer` это учитывает.
- **Предзагрузка модулей** в начале фиксера нужна, чтобы под `-WhatIf` автозагрузка не печатала строки «What if: New Alias».
- **Порт 9100 не опрашивается никогда**: пустое подключение принтер может принять за задание печати.
- **Сверка MAC работает только в одном L2-сегменте.** Через VPN или маршрутизатор скрипт откажется работать, если MAC задан. Пустой `PrinterMac` отключает проверку.
- **Порядок «подключение → чтение ARP» важен:** запись в ARP-кэше появляется после обмена пакетами.
- **Удаление WSD-очереди удаляет в Windows всё сетевое устройство вместе со сканером.** Сканер считается «своим», пока не доказано, что у него другой IP; отсюда защита `$protected`.
- **Правило «адрес известен и другой → `Other`» стоит раньше правил по имени и шаблону.** Это защищает второй принтер той же модели. Побочный эффект: старая очередь этого же принтера на порту с прежним буквальным IP не будет распознана (кроме очереди с именем `QueueName`).
- **Очереди факса по умолчанию не удаляются** — в версии для Pantum было наоборот (`-KeepFax`).
- **Имена разрешаются с таймаутом 4 с** (`Resolve-HostIPs`); мастер на ПК с несколькими портами на мёртвые имена работает до минуты.
- **Сторож ищет только в подсетях /24** и не пишет «всё в порядке» в лог — только на экран.
- **Планировщик запускает копию сторожа** из `%ProgramData%`: после правки скрипта нужен повторный `-Install`.
- **Дублирование.** `Test-IsAdmin`, `Measure-TcpConnect`, `Get-MacByIP`, `ConvertTo-Mac`, `ConvertTo-NativeArgument`, `Read-ConfigFile` есть в обоих скриптах, потому что сторож копируется одним файлом. Правки вносить в обоих местах.
- **Лаунчер делает `pause` всегда, кроме кода 99** — чтобы окно не закрылось раньше, чем пользователь прочитает вывод мастера или ошибку.

## Что нельзя менять без согласования

- **Защитные механизмы:** сверку MAC, бэкап PrintBrm перед изменениями, запрос подтверждения плана, исключение USB/LPT/COM/виртуальных портов и принтеров с `Type` не `Local`, правило `Other`, защиту WSD-очередей сканера, отказ от опроса порта 9100, поддержку `-WhatIf`.
- **Имена, по которым находится уже установленное:** папку `%ProgramData%\PrinterWiFiFix`, префикс задачи `Printer Wi-Fi Watchdog - `, схему имени порта `IP_<адрес>` (и `IP_<адрес>_<порт>` для нестандартного порта), имена ключей в `printer.psd1`.
- **Кодировку и переводы строк** скриптов.
- **Проверять правки через `-WhatIf` и `-Setup`.** `Fix-PrinterWiFi` без этих ключей и `Printer-Watchdog.ps1 -Install`/`-Uninstall` меняют системные очереди печати и планировщик — запускать их только там, где это действительно нужно.
- **Не коммитить `printer.psd1`** и не добавлять в документацию и тесты реальные IP, MAC, имена хостов и компьютеров.
